# Неделя 7, этап C2: план бенчмарков (только план, ничего не запущено)

Общие условия для всех серий:
- `cbm.exe`: код такой же, как в этапе B. После a883df5 в `cbm.cpp`, `bs_team.hpp`, `flow_team.hpp` добавлен
  только комментарий (16d8791). Поэтому строки этапа B (R20261117-big-match) можно брать как есть, не пересчитывая;
- `--t-start match`;
- память 8000 МБ;
- запуски строго по одному;
- каждое решение проверяет `validate.py`;
- CSV дописывается после каждого запуска.

Варианты: bs, bspen, bscut, floww. flow не берём: в этапе B он везде хуже floww.

ID каждой серии назначен заранее и передаётся через `--run-id`. Дата в ID — день, когда серия запланирована
к запуску; если запуск сдвинется, ID останется тем же.

**Как оценено время.** Оценки взяты из `wall_s` этапа B (10 карт × 10 сценариев, 5,6 ч на 5 вариантов):
- тайм-аут стоит 60 с на малых картах и 61-62 с на городах (загрузка карты);
- работает правило пропуска: если вариант не решил задачу, большие N того же сценария не запускаются. Значит, в
  серии по N у каждой тройки (карта, сценарий, вариант) не больше одного тайм-аута;
- время решённых задач растёт с N. В оценке я считаю (догадка), что каждый следующий шаг N в 2,5 раза дольше
  предыдущего.

## Серия A. Число роботов — `R20261120-c2-agents`

**Зачем.** В этапе B bspen и bscut решили почти всё на всех 10 картах (bscut 399 из 400). Различия между ними видны
только при больших N.

**Что запускаем.** Те же 10 карт, сценарии 1-10, команды по 5, лимит 60 с. N продолжают ряды этапа B:

| группа карт | N в этапе B | новые N |
|---|---|---|
| 32×32 (empty, random, room, maze) | 20, 40, 60, 80 | 100, 120, 140, 160 (в room-32-32-4 и maze-32-32-2 в сценарии 333-341 робот, этого хватает) |
| 64×64 (random-64-64-10, room-64-64-8) | 40, 80, 120, 160 | 200, 240, 280, 320 |
| warehouse, Berlin, Paris, Boston | 64, 128, 192, 256 | 320, 384, 448, 512 |

Запускаются только последовательности (карта, сценарий, вариант), которые решили самое большое N этапа B
(`--continue-from`). Сколько таких: bs 31, bspen 76, bscut 99, floww 58 из 100 у каждого варианта.

**Что меряем:** решено или нет, `total_ms`, T, число узлов CT, `root_ms`, `root_conflict_pairs`, `peak_mb`.

**Время:** около 5,5 ч. По картам — от 5 до 21 мин на вариант; города у bspen и bscut — около 20 мин каждый.

**Графики:**
- кактус (решено задач от времени) по группам «малые» и «большие», этап B + A вместе;
- доля решённых от N по каждой карте (4 линии вариантов);
- медиана узлов CT от N (по решённым);
- медиана `root_ms` от N.

## Серия B. Число команд при фиксированном числе роботов — `R20261121-c2-teams`

**Зачем.** Число команд меняет задачу:
- при K = 1 это одна команда, корень и есть решение;
- при K = N это обычный MAPF с метками.

Конфликтов CT и работы штрафа должно быть больше при большом K. Это догадка, её и проверяем.

**Что запускаем.**
- Карты: room-32-32-4 и maze-32-32-2 (N = 60), room-64-64-8 (N = 120), warehouse и Berlin (N = 192). Это N, где
  в этапе B bspen и bscut решают, а bs и floww уже часто нет.
- K ∈ {1, 2, 4, 8, 16, 32}. Точка «по 5» (K = 12, 24, 39) уже есть в этапе B.
- Сценарии 1-10, лимит 60 с, без правила пропуска (сложность от K не обязана расти монотонно).
- Варианты: bspen, bscut, floww. bs предлагаю не брать: при этих N он почти везде упирается в 60 с, это ещё 3,7 ч
  тайм-аутов.

Всего 5 карт × 6 K × 10 сценариев × 3 варианта = 900 запусков.

**Что меряем:** то же, что в A, плюс число команд в конфликтах корня.

**Время** (по долям тайм-аутов этапа B при этих N; K = 1 и 2 быстрые): около 3,7 ч без bs, около 7,4 ч с bs.

**Графики:**
- доля решённых от K по каждой карте;
- медиана времени от K (по решённым всеми тремя);
- медиана узлов CT от K;
- `root_conflict_pairs` от K.

## Серия C. Лимит времени — `R20261122-c2-limit300`, затем `R20261122-c2-limit600`

**Зачем.** Проверить, тайм-ауты при 60 с — это «чуть-чуть не хватило» или «безнадёжно». Задачи, решённые за
60 с, при большем лимите решатся так же (поиск детерминирован), поэтому их не повторяем.

**Что запускаем.** Подмножество:
- карты maze-32-32-2, room-64-64-8, warehouse, Berlin;
- варианты bspen, bscut, floww;
- первая не решённая задача каждой последовательности в этапе B: bspen 21, bscut 1, floww 22, всего 44 задачи.

Шаги:
- 300 с: если задача решилась, правило пропуска продолжает последовательность к следующему N;
- 600 с: только то, что осталось не решённым при 300 с.

По желанию сюда же добавляются первые тайм-ауты bspen и bscut из серии A на тех же картах. Их число станет
известно только после A, до 40 задач, это ещё до 3,3 ч при 300 с.

**Время:** 300 с — не больше 3,7 ч (44 × 300 с). 600 с — не больше 44 × 600 с = 7,3 ч; догадка: реально 2-4 ч.

**Графики:**
- по вариантам: сколько из тайм-аутов 60 с решено при 300 и при 600 с;
- кактус до 600 с на этом подмножестве;
- для решённых: T и число узлов CT против последнего ключа (`last_key`) при 60 с, то есть как далеко был ответ.

## Команды запуска

Запускать из `experiments/`, по одной серии, в этом порядке. Перед каждой: в репозитории нет изменённых файлов кода
(`git status`), `cbm.exe` собран из текущего коммита. Прерванную серию продолжает та же команда с `--resume`.

**A** (около 5,5 ч):
```
python cbm_bench_cactus.py --run-id R20261120-c2-agents --note "C2 A: N beyond stage B" --variants bs,bspen,bscut,floww --ns "32:100,120,140,160/64:200,240,280,320/large:320,384,448,512" --continue-from cbm_bench_cactus_match.csv --time-limit 60 --mem-limit 8000 --t-start match
```
После: `python cbm_bench_cactus.py --summary runs/R20261120-c2-agents/results.csv`;
`python figures/make_cactus.py cbm_bench_cactus_match.csv,runs/R20261120-c2-agents/results.csv`;
`python figures/make_c2.py by-n cbm_bench_cactus_match.csv,runs/R20261120-c2-agents/results.csv`.

**B** (около 3,7 ч):
```
python cbm_bench_cactus.py --run-id R20261121-c2-teams --note "C2 B: teams at fixed N" --maps room-32-32-4,maze-32-32-2,room-64-64-8,warehouse-10-20-10-2-1,Berlin_1_256 --variants bspen,bscut,floww --ns "room-32-32-4:60/maze-32-32-2:60/room-64-64-8:120/large:192" --teams 1,2,4,8,16,32 --no-skip --time-limit 60 --mem-limit 8000 --t-start match
```
