# experiments/

CBM для цветного MAPF с критерием makespan. Цветной MAPF: роботы разбиты на команды, и каждый робот должен прийти
в какую-нибудь цель своей команды, а в какую именно, не важно. Makespan: момент, когда последний робот встал в
свою цель.

CBM устроен в два уровня:
- **верхний уровень** — дерево CBS над командами. Если роботы двух разных команд сталкиваются, то в двух узлах-детях
  одной из команд запрещают эту клетку (или ребро) в этот момент;
- **нижний уровень** — план одной команды при её запретах: самый маленький T, при котором вся команда доходит до
  целей, и маршруты роботов. Вариантов нижнего уровня пять (`--low`, ниже).

Подробные старые заметки (как запреты кодируются в сети, ранние проверки): `NOTES.md`.
Журнал разборов и замеров: `small_maps_diag.md` (оглавление в начале файла).

## Варианты нижнего уровня (`--low`)

| `--low` | Что это | Смотрит на чужие команды? |
|---|---|---|
| `bs` | Bulk Search: поиск по сети «клетка × время» из AMAPF-MF-BS, переписанный под одну команду | нет |
| `bspen` | Bulk Search, но среди путей с тем же T выбирает те, что меньше мешают другим командам (штраф за клетку или ребро, занятые чужим роботом в тот же момент) | да |
| `bscut` | `bspen` плюс «мягкие разрезы»: в `bspen` стоять на месте бесплатно, даже если в клетку в это время придёт чужой робот; в `bscut` такое ожидание тоже штрафуется. Разрезы ставятся вокруг моментов, когда в клетке чужой робот (`--cut penal`, по умолчанию), или на каждом шаге (`--cut all`) | да |
| `flow` | максимальный поток в развёрнутой по времени сети (статья CBM, раздел 2.2) | нет |
| `floww` | `flow` плюс поток минимальной стоимости: те же штрафы за чужих роботов (статья CBM, раздел 3.2) | да |

T у всех пяти одинаковый: это проверяют тесты (ниже). Отличаются только маршруты, а значит, и число конфликтов,
которые потом разбирает верхний уровень.

## Что в каком файле

Код (C++):
- `cbm.cpp` — CBM целиком, программа `cbm.exe`; описание всех флагов в начале файла;
- `bs_team.hpp` — нижний уровень `bs` / `bspen` / `bscut` (`bs::BulkSearchTeam`), карта `bs::Grid`, общие функции
  (чтение .scen, запись маршрутов, BFS, оценки начального T);
- `flow_team.hpp` — нижний уровень `flow` / `floww` (`bs::FlowTeam`);
- `bs_team.cpp` — одна команда без CBM (`bs_team.exe`), нужна для тестов;
- `bs_single.cpp`, `bs_trace.cpp`, `flow_ref.cpp` — исходный Bulk Search без изменений, он же с печатью путей,
  и независимый простой поток; это эталоны для проверок.

Скрипты прогонов:
- `cbm_bench_cactus.py` — большой прогон для графиков cactus (см. ниже);
- `cbm_bench.py`, `cbm_paper_exp1.py` — прогоны этапов 3 и 5.1 и опыт 1 статьи CBM; из них остальные скрипты берут
  общие функции (`map_and_scen`, `grouped_scen`, `field`, `load_grid`);
- `week6_part1.py` — сводка из уже посчитанных CSV (без запусков);
- `make_empty_maps.py` — свои пустые карты 128×128 и 256×256 в `maps/`.

Проверки (запускать после любых правок кода):
- `validate.py` — независимая проверка файла маршрутов: старты, ходы, цели, столкновения;
- `brute_force.py` — точный ответ полным перебором (только крошечные карты);
- `test_flow_team.py` — нижний уровень (`bs_team.exe`, все пять вариантов) против перебора;
- `compare_cbm.py` — `cbm.exe` против перебора на случайных крошечных задачах;
- `compare_cbm_exe.py` — два `cbm.exe` на 16 трудных задачах: все поля вывода, кроме времён, должны совпасть;
- `compare_brute.py`, `compare_exe.py` — то же для одной команды (`bs_single` / `bs_team`);
- `check_match_bound.py` — проверка оценки `--t-start match`.

Результаты: новые прогоны в `runs/<ID>/` (список: `runs/REGISTRY.md`); старые `*.csv` и `*.md` рядом со
скриптами, рисунки в `figures/`, сырые логи профиля в `week6_prof/`. `runlib.py` — ID прогона, manifest, реестр.
`archive/` — одноразовые скрипты разборов, их результаты уже в журнале (список в `archive/README.md`).
`t/` — крошечные задачи для ручных проверок.

Карты и сценарии MovingAI лежат в `../data/` (`mapf-map/`, `mapf-scen-random/`).

## Как собрать

Windows, MinGW. Из корня репозитория:
```
.\experiments\build.ps1
```
Собирает все `.exe`, в том числе `cbm_prof.exe` — тот же `cbm.cpp` с подробным профилем времени (`-DBS_PROFILE`,
печатает строки `prof ...` в stderr). Если MinGW лежит не в `C:\ProgramData\mingw64\mingw64\bin`:
`.\experiments\build.ps1 -MinGW D:\путь\к\mingw64\bin`.

## Как запустить одну задачу

```
experiments/cbm.exe MAP.map FILE.scen N K [ROUTES|-] --low bspen --t-start match --time-limit 60
```
- `N` — сколько первых строк .scen взять (роботов), `K` — сколько команд: робот i попадает в команду i % K;
- `ROUTES` — куда записать маршруты (`-` — не записывать); проверить их: `python experiments/validate.py MAP.map
  FILE.scen N ROUTES --teams K`;
- `--t-start` — с какого T нижний уровень начинает поиск: `1`, `lb` (по умолчанию: самое большое расстояние
  от старта робота до ближайшей цели его команды) или `match` (оценка через назначение роботов целям; обычно
  ближе к ответу). Ответ от этого не меняется, меняется только время;
- `--time-limit`, `--max-nodes`, `--mem-limit` — пределы по времени (с), числу узлов дерева и памяти (МБ).

Команды по 5 роботов, как в прогонах: сценарий с переставленными строками делает `grouped_scen` из
`cbm_paper_exp1.py`, и `K = ceil(N / 5)`.

Вывод — одна строка `status=solved|timeout|node_limit|memory T=... nodes_generated=... ...`; `T=-1` — решение не
найдено в пределах. Остальные поля описаны в начале `cbm.cpp`.

## Как повторить большой прогон

```
python experiments/cbm_bench_cactus.py --name big-match --t-start match --scens 1-10 --time-limit 60 --mem-limit 8000
python experiments/cbm_bench_cactus.py --summary experiments/runs/R20261124-big-match/results.csv
python experiments/figures/make_cactus.py experiments/runs/R20261124-big-match/results.csv
```
Каждый прогон получает ID `R<ГГГГММДД>-<имя>` (`--name`; или `--run-id` целиком) и папку `runs/<ID>/`:
`manifest.json` (даты начала и конца, коммит и есть ли незакоммиченные изменения, все параметры, машина),
`results.csv` (колонка `run_id`), `run.log`. Таблица всех прогонов: `runs/REGISTRY.md`, создаётся из manifest
(`runlib.py`). Прогоны до появления ID внесены туда задним числом; их файлы остались на старых местах.
Рисунки называются `<ID>__...png` и подписаны снизу: ID, карты, лимит, команды, старт T.
Карты: 6 маленьких (32×32 и 64×64) и 4 большие (warehouse, Berlin, Paris, Boston), сценарии 1–10, все пять
вариантов, команды по 5. Внутри сценария N растёт; если вариант не решил задачу, большие N этого сценария для него
не запускаются (`timeout_skipped`). Запуски идут строго по одному, каждое решение проверяется `validate.py`, CSV
дописывается после каждого запуска; прерванный прогон продолжает `--resume --run-id ID` (с теми же параметрами). Выбор подмножества: `--maps`,
`--variants`; `--t-start lb|1|match` передаётся в `cbm.exe` (по умолчанию `lb`).
Полный прогон идёт много часов (до 60 с на задачу).
